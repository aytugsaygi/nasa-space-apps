# Health Atlas · Mürettebat Sağlık Konsolu

NASA Space Apps Challenge 2026 Ankara için astronot sağlık takibi arayüzü (prova prototipi). Eski çalışma adı Vitalis'tir; kayıt anahtarları (`vitalis.*`) ve veritabanı dosyası bu adı korur.

- `arayuz/`: Vite + React + TypeScript uygulaması ve sunucusu
  - Dört sayfa: ana sayfa (günlük mini grafikli göstergeler, 3D anatomi hologramı, yapılacaklar), zihinsel sağlık (Cupola, nefes, zihin egzersizleri, ruh hali, günlük), spor (hologram antrenör, şikayete göre program), sağlık kayıtları (grafikler, kan tahlilleri, rapor, uzay havası)
  - Tek asistan (Sağlık Asistanı: koç, dinleyen, arkadaş; kural tabanlı, SI kullanmaz), uçuş hekimi profili, demo senaryoları, TR/EN
  - Sunucu: kural tabanlı analiz, simülasyon, SQLite veritabanı, NASA verisi (OSDR, DONKI, EPIC)
- `submission/`: teslim metinleri (İngilizce)
- `CREDITS.md`: galerideki fotoğrafların yazarları ve lisansları; `SI-DISCLOSURE.md`: SI ile üretilen içerikler

## Çalıştırma

Node.js 22.13 veya üstü gerekir (Node 24 önerilir).

```
cd arayuz
npm install
npm run dev
```

Tarayıcıda http://localhost:5173 adresini aç. Geliştirme sunucusu API'yi de açar; veri `arayuz/data/vitalis.db` dosyasında tutulur.

Yayın sürümü: `npm run build && npm run build:server`, ardından `npm start` (http://localhost:8787).

## Testler

```
cd arayuz
npm test                          # birim, bileşen ve sunucu testleri (Vitest)
npx playwright install chromium   # yalnızca ilk sefer
npm run test:e2e                  # uçtan uca testler ve görsel karşılaştırma (Playwright)
```

## Feasibility and cost

Health Atlas needs no new hardware or paid software; the real costs are development effort and, for real use, medical software approval and flight certification. No price figures are given unless verified on an official page; none were.

| Item | Today | In real use | Basis |
|---|---|---|---|
| Development | Open-source tools (TypeScript, React, three.js, Node.js, SQLite); no licence fees, the cost is team effort | A small software team for maintenance and validation | Software licences (Sources dialog) |
| Hardware | No new hardware; runs in a browser (tablet, laptop) | Sensor data comes from existing wearables (e.g. CSA Bio-Monitor) | [CSA Bio-Monitor](https://www.asc-csa.gc.ca/eng/sciences/bio-monitor.asp) |
| Software and model licences | MIT, Apache 2.0, ISC; anatomy model CC BY-SA 4.0; trainer model CC0; equipment models CC BY 3.0 and CC0 | Same; no fees | Sources dialog |
| Data | NASA DONKI, EPIC and OSDR are public; DONKI and EPIC are fetched without an API key, with an embedded snapshot when offline | Same | DONKI, EPIC, OSDR |
| Operations | A single-process Node.js server and SQLite; works offline; no cloud services | One server on the ground or the computer on board | Architecture (above) |
| Language model | Not connected; the assistant is offline and rule-based | Optional and the only usage-based cost; if turned off, the offline answers keep working | No price given |
| Moving to real use | None (prototype) | Medical software approval, a cybersecurity audit and flight certification; the cost depends on the agency's process | No figure given |

**Resources and funding.** NASA's Human Research Program tracks and studies the health risks of spaceflight, and the Canadian Space Agency develops wearable systems that measure crew health. Health Atlas addresses the same problem. Every component is openly licensed, so agencies, universities and analog mission teams can reuse the code under the Apache License 2.0 (`LICENSE`).

**Economic sustainability.** Thresholds live in one file (`arayuz/src/core/catalog.ts`) that a flight surgeon can change; when NASA data changes only the snapshot is refreshed (`npm run nasa:snapshot`); the same tool can be reused in NASA's analog missions on Earth.

_This table assesses a hackathon prototype; the real cost depends on the agency's requirements and approval process._

## Limitations and roadmap

| Today | In real use | Already in the app |
|---|---|---|
| Crew data comes from a simulation | Sensor and medical device data enter through the import layer | Data import screen (CSV/JSON, column mapping, unit conversion); an imported series replaces the simulation in its time range |
| No authentication; the role is chosen in the browser | Sessions and role checks on the server, encrypted storage | Every action goes through a single RPC layer on the server |
| The assistant is offline and rule-based | A language model connected through the server; the key never reaches the browser | The crisis rule and action buttons work without a language model and are tested |
| Some thresholds are Health Atlas rules; SpO₂ and blood sugar use general clinical thresholds | A flight surgeon sets the thresholds | Thresholds live in one file; each band's basis is shown in the "NASA data" tab |
| Delayed contact with the flight surgeon is simulated | A real communication link (e.g. delay-tolerant networking) | Delay and blackout logic is in the engine; messages wait in a queue |
| It does not diagnose | An approval process as a decision-support tool | A "does not diagnose" note on the screens and in the report |
| Tests: 463 unit and component tests (Vitest) and 111 end-to-end tests (Playwright, including axe accessibility scans); all passed in the last run (14 November 2026) | Independent clinical validation | Unit, component, end-to-end and accessibility (axe) tests |

Next steps: (1) a pilot in an analog mission such as HERA or CHAPEA, (2) validation with real sensor data and thresholds set with a flight surgeon, (3) a security audit and medical software approval.

## Impact

See `submission/impact.md`. In short: on Mars a message to Earth takes about 3 to 22.5 minutes one way, so the crew must understand their own health. The same tool fits NASA's analog missions on Earth (HERA, CHAPEA) and other isolated crews that NASA studies, such as submariners and people who live in Antarctica.
